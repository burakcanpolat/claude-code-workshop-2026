Working With Claude Code

Participant handbook, 19 September 2026

Claude Desktop app/Code tab/VeloMax GmbH, one fictional company all day

Today one folder of messy sales exports turns into a small working system: a briefed assistant, a written procedure, an installed bundle, a connected inbox, a monthly report and a schedule that produces it. The trainer does every step live. If you have the Code tab you do the same step on your own copy, at your own pace. If you do not, you watch, and you repeat it tonight from this page. There is no code to write.

Three roles, and all three of them are real

Nobody is timed today. There is no "you have ten minutes, go". Pick the role that matches the machine in front of you and stay in it without apologizing for it.

▶ The trainer

Demonstrates every step live in the Claude Desktop app, on a real folder, immediately after explaining the idea behind it.

▶ You, with the Code tab

Do the same step on your own copy of the kit, whenever you are ready. Nobody waits for anybody. If you fall behind, keep watching: the steps are on this page under the same unit number, so you can catch up during the next explanation or tonight.

▶ You, without the Code tab

Watch. Every live moment on this page has a Watching only? Notice line that tells you exactly what to look at, and you repeat the whole thing tonight with the kit and this page.

Two kinds of live moment FOLLOW ALONG means everyone with the Code tab does it too. WATCH means the trainer does it and the room watches, either because it touches a real account or because it would not be safe to repeat on a shared screen. Each unit card below is labeled with one of the two.

Get the kit

  1. Download the kit: VeloMax-Workshop.zip (about 280 KB, synthetic data only).
  2. Unzip it somewhere plain and local: your Desktop or your Documents folder. Not inside a synced OneDrive or SharePoint root, and not inside a work folder that holds real client material.
  3. Keep the whole folder together. Every prompt today assumes you opened the session on VeloMax-Workshop itself, not on the CRM subfolder inside it.
  4. Leave it alone otherwise. The data is synthetic, the company is fictional, and nothing in it is confidential. That is what makes it safe to point a new tool at.
Why German column names The CRM exports and the dashboard are in German on purpose. That is what a real export from a real company looks like, and Claude handles it without anybody translating anything first.

Install check, before 09:00

  • Use Help, then Check for Updates, once, before we start.

  • The Code tab needs Pro, Max, Team or Enterprise. On Free, clicking Code prompts you to upgrade. If you cannot see it, you are in the watching role today, and that is a real role.

  • You should see 01_CRM_Rennradhersteller/, dashboard/, _staging/, templates/ and four small text files at the top of it.

  • Only the dashboard picture in Block 3 needs it. Without Python you do every step, and Claude reads the CSV files directly instead. You lose the picture, not the work.

What you will have built by 13:00

the build map: before on the left, after on the right

Left is the folder you unzip tonight. Right is the folder you have at one o'clock. Every addition carries the unit number that adds it, so you can always answer the question "where are we and what are we building". Thirteen additions, four hours, no code.

The day map

three blocks, twenty-five units, one folder

A filled station is a FOLLOW ALONG unit. A ring is a WATCH unit. Block 1 is the worker and your brakes, 09:00 to 10:30. Block 2 is everything that makes the second month cheaper than the first, 10:50 to 12:10. Block 3 is the loop that runs without you, 12:20 to 13:00.

Your screen will not look like the trainer's

Three things make everybody's window slightly different, and none of them is a broken installation.

  1. The tab bar is moving this month. On 16 September 2026 Anthropic announced that Claude Cowork and chat are now one Claude, rolling out to Pro and Max first, then Team and Free, with Enterprise admins given at least 30 days' notice.
  2. Plan gating. The Code tab needs Pro, Max, Team or Enterprise.
  3. Your IT department. On Team and Enterprise an admin decides what appears in your app, including whether local sessions are allowed at all. If something is grayed out today, that is policy, not a bug.
The only safe instruction Read your own selector, read your own model list, read your own menus, and say what they show. Nothing on this page depends on a version number, and none is printed anywhere in it.

How to use this page

▶ Part A is for doing

One card per unit, in day order, with every prompt and command as a copy block in the order it appears on screen. No theory in the steps. Each card links to the reference section that explains it.

▶ Part B is for understanding

Nineteen reference sections: the concepts, the diagrams, the tables, the safety sheet, the templates and the glossary. Read it tonight, or when somebody asks you a question next week.

▶ It remembers, and it exports

Every card and every reference section has a My notes box that saves in this browser only. Export my notes downloads everything you wrote as one markdown file. Print or save as PDF gives you a clean paper version. Do both before you close the tab.

Shortcuts are printed in both variants, macOS first: Cmd+Shift+M/Ctrl+Shift+M. Storage is per browser: if yours blocks it, the page still works, it simply forgets.

1.6 Failing safely 09:50 . 6 min

What happens. The trainer breaks it on purpose with a bundled prompt, presses Esc, clears, and re-asks the same job with a scope. Following along is optional, and if you do, do it on a throwaway copy.

Shows Esc, clear, re-ask with one scope
  1. In the same folder, in Manual, paste P3 and send. Manual is the safety net: nothing lands without you.
    P3The deliberately bad prompt
    Reorganise everything in here, fix all the problems, rename files sensibly and make it all consistent.
  2. Watch the first two or three tool calls, then press Esc. If a permission prompt appears first (it wants to move or rename files), do not allow it: that prompt is the brake working. Never switch to Accept edits here.
  3. Clear the conversation.
    >command
    /clear
  4. Paste P4 and send.
    P4The same job, scoped
    In this folder, list every opportunity in opportunities.csv whose status is still open but whose most recent entry in aktivitaeten.csv is older than 90 days. Give me a table with customer, owner, value in EUR and days since last activity. Do not change any file.

You should see A sweeping plan across several fronts that finishes none of them, then a clean named table within seconds from the scoped version. In Manual, nothing on disk changed at any point.

Watching only Count how many different jobs the first prompt started and how few it finished, then notice how fast the second one landed.
If it goes wrong If the scoped prompt finds nothing, change 90 days to 30. You are changing the threshold, not the structure of the prompt. If /clear is not in your menu, start a new session instead.

How Claude works: the loop and the tools

units 1.4, 1.8

Claude Code is not a text box that answers. It is a loop: gather context by reading things, take an action, check the result, and go round again until the job is done or you stop it.

gather, act, verify, repeat

A question may need only the first pass. A change may go round many times. The loop is bounded by two things you already chose: the folder, and the permission mode. The interesting question is never what it said. It is what it chose to read.

Five things it can actually do

▶ Read and write
  • Read a file
  • Write or change a file
▶ Act and search
  • Run a command on your machine
  • Search the web
▶ Look around
  • Look through a folder and find things

Everything you hear about today is one of those five with a better name on it.

Esc, precisely

The documented meaning of Esc in this app is "Stop Claude's response". The work so far is kept. It is a stop button, not an undo. Your undo is Reject in Manual mode, and it is in R4.

Permission modes and where the data goes

unit 1.5

The permission mode is a dial that decides how much Claude may do without asking. The diff is the receipt for anything it does.

the trust dial, and the gate underneath it

The dial is how much it may do without asking. The gate under it is the diff. You decide what it is allowed to do, and you review each change before it lands.

ModeIn the product's own words
ManualClaude asks before editing files or running commands. You see a diff and can accept or reject each change. In Manual mode, your files are not modified until you accept.
Accept editsClaude auto-accepts file edits and common filesystem commands, but still asks before running other terminal commands.
PlanClaude reads files, runs commands to explore, and writes you a plan, but it does not edit your source. Anthropic's own guidance is to start complex tasks in Plan and then switch. Plan applies to the current session only.
AutoClaude executes all actions with background safety checks. It needs a recent model (Opus 4.6 or later, Sonnet 4.6 or later, or a Fable model); if that is unavailable the session starts in Manual.
Bypass permissionsIt exists, it is documented for sandboxed containers and virtual machines, and it is the wrong setting for a beginner. On a company plan you probably cannot turn it on anyway.
Read your own selector Do not assume you are in the same mode as anybody else. The documented starting mode depends on your plan, your app version and your IT settings, and Anthropic's own table for that is written for terminal and editor sessions, not for this app. The first session after a fresh install can land in either mode. The only correct instruction is: read your selector.
The per-folder trap A mode you pick in the selector is remembered for that folder and takes precedence over any settings file. Plan is the exception and applies to the current session only. So if you practice in Accept edits, the folder remembers, and the permission prompt you wanted to see never appears.

Auto mode, with the honest numbers

  • Claude Code users approve 93% of permission prompts. That is a fact about people, not about the software. Anthropic built Auto mode because of approval fatigue, where people stop paying close attention to what they are approving.
  • The classifier wrongly blocks about 0.4% of safe actions: about four in a thousand.
  • It misses about one risky action in six, so it catches roughly five in six.
  • Anthropic's own warning, verbatim: "Auto mode reduces permission prompts but does not guarantee safety."
  • It is deliberately kept blind to Claude's own reasoning: it sees your messages and the exact command, not the story Claude tells about why the command is fine. Think of fraud detection on a bank card, not a human approving every transaction.

Your undo ladder, in this order

  1. Prevention. Stay in Manual, read the diff, click Reject. Nothing was written.
  2. If something was written. Open the diff pane and ask Claude in plain language to put it back.
  3. Maybe. Type / and look for rewind. It may be there on your machine.
  4. The real backstop. A plain copy of the folder made before you started.
Do not build your safety on undo Undo is not documented for this app. The Desktop documentation does not mention rewind, checkpoint or undo. Check on your own machine whether rewind is in your slash menu, and stay in Manual either way.

Where the data goes

opened files travel, unopened files do not

The folder stays on your disk. The files it opens travel. The files it never opens never leave. That is the whole data story in one picture.

Nothing is installed on your machine to watch your files, and Claude Code does not sync your drive anywhere. But the text of every file Claude actually opens travels to Anthropic's API as part of the request; that is how the model reads it. Files it never opens never leave. CLAUDE.md, the standing brief

unit 2.1

CLAUDE.md is a plain Markdown file in your folder, and the mechanism is one sentence: Claude reads it at the start of every session. That is why a four-line file changes the output more than a cleverer prompt does, and it is also why editing it mid-conversation changes nothing until you start a new session.

one arrow, and it only fires at the start of a session

Everything hard about this file comes from that one arrow. It is the standing brief on a new employee's desk, read fresh every morning, before they speak to anybody.

▶ What goes in it: rules, not description

▶ What does not go in it
  • A long procedure with sections and an output format. That is a skill, R10.

Ultracode and dynamic workflows

units 2.8, 3.1

Ultracode is a Claude Code setting, not a model and not an effort level, and it turns on two things at once: it sends xhigh to the model, and it has Claude orchestrate a dynamic workflow.

the orchestrator writes the plan, then the phases run

The middle box is the thing people miss. It does not spawn a fixed number of helpers. It writes a plan of attack first, and the number of helpers falls out of what it found.

What a dynamic workflow actually is

  1. Claude reads the task and writes a script that describes how to attack it.
  2. The runtime executes that script in phases: a sweep, then a verification, then a synthesis.
  3. The sweep spawns as many agents as there are angles it actually found. The agent count is a consequence of the material, not a setting you pick, which is why the same command behaves differently on a small folder and a large one.
  4. Findings are cross-checked before being reported, and one file comes out at the end.
  5. The chat stays responsive while all of it runs in the background.
What it costs, in Anthropic's own words "A workflow spawns many agents, so a single run can use meaningfully more tokens than working through the same task in conversation." For the record, the documented limits are up to 16 concurrent agents by default and 1,000 agents total per run, with a size guideline that defaults to smaller on Pro.
On Pro, turn workflows on first Workflows are available on all paid plans, but on Pro you switch them on from the Dynamic workflows row in /config. If you type ultracode on Pro and nothing happens, that is why.
▶ When it is worth it
  • A question that genuinely has several independent angles.
  • A body of material too large to hold in one conversation.
  • Something you are going to act on.
  • A moment when you can start it and go and do something else.
▶ When it is not
  • Anything you could have asked in one scoped prompt.
  • Anything you need an answer to in the next two minutes.
  • Every day. This is a once-a-week button.

Safety sheet

unit 3.7, and Monday

The question is never whether Claude Code is safe. It is which folder you pointed it at.

▶ Do not point it at this on Monday
  • Client or employee personal data: CVs, ID numbers, health records, customer lists.
  • Payroll and HR files.
  • Anything under an NDA or a client confidentiality clause.
  • Shared network drives and department-wide folders.
  • A whole synced OneDrive or SharePoint root.
  • Credential stores, .env files, key material, VPN configuration.
  • Documents that arrived from outside your company.
  • A personal Pro account used for company work. There is no DPA behind a personal account.
▶ Do this instead
  • A new, empty folder per task. Copy in only what the task needs.
  • Permission prompts on, which means Manual mode, for the first week.
  • The company account, not the personal one.
  • Remember there is a plaintext transcript of the session on your own disk, under your home folder.
  • If you are unsure whether a folder is fine, it is not.

A document is an instruction Claude will read

Claude reads a document the same way it reads your instructions: as text. It cannot reliably tell "this is the content I was asked to summarize" from "this is an instruction". So somebody can write instructions inside a document, in one-point white text on a white background, with the line spacing squeezed to nothing. You see a normal invoice. Claude sees a sentence telling it to collect other files from your folder and send them somewhere. Within two days of the Cowork launch in January 2026, security researchers demonstrated exactly this against the Cowork assistant: a Word document that made it upload real financial files to an account the attacker controlled. The mechanism applies to any agent that reads documents it did not write. The rule is simple. A document that came from outside your company is not an instruction you have read. It is an instruction Claude will read. Put it in its own folder, keep the prompts on, and never run it unattended on a file you did not write. Say this once, slowly, and do not rush it
Anthropic's own words "No system is completely immune to all attacks." "Avoid piping untrusted content directly to Claude." And for connectors: "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk."

  2. Are Local sessions allowed on my managed device, or only Cloud? There is a managed setting that leaves Local visible but grayed out.
  3. Which permission modes are available to me? Is Auto mode enabled or disabled for the organization? Is Bypass permissions blocked?
  4. Which connectors are allowed? Admins can allow, deny, or force a managed list. Microsoft 365, Google Workspace, Slack, Jira, Trello, Notion and others exist in the catalogue.

  8. Do we have Zero Data Retention? Enterprise only, arranged with Anthropic, not a toggle in admin settings. Prefer checklists to prose. Say what is blocked, by what, and who owns the next step. <!-- HR --> Write for an HR audience. Never include a person's name unless I put it in the prompt myself. Describe patterns, not individuals. Flag anything that looks like personal data. <!-- MANAGEMENT --> Write for a management audience. Three lines of summary first, then the detail. End with the one decision you would ask me to make. <!-- DEVELOPERS --> Write for a technical audience. State assumptions explicitly. Prefer a small, reviewable change over a large one. Say what you did not check.

>templates/SKILL.md
--- name: monthly-brief description: Use when writing a monthly management brief for VeloMax from a monthly analysis file or from a month folder of CRM data. Use it whenever someone asks for the monthly report, the management summary, the monthly brief, or the month-end commentary. Produces the house format: summary, facts, inferences, anomalies, next steps. --- # Monthly management brief, VeloMax house format ## When this applies A month has closed and somebody needs the standing management brief for it. The source is normally `dashboard/analysis/<YYYY-MM>.json`, or the month folder under `dashboard/data_snapshot/<YYYY-MM>/` when no analysis file exists yet. ## Gotchas, read these first - Never write a number that is not in the source. If a figure is missing, write "not in the source data" and put it in the Anomalies section. Do not estimate. - The source column names are German. Do not translate them inside tables; translate them only in prose, and keep the German name in brackets the first time. - If both an analysis file and raw CSVs exist for the month, use the analysis file and say so. - A month with fewer than 20 transactions is not a trend. Say that in the text rather than drawing a conclusion. - Compare to the immediately preceding month, and only to that month, unless asked otherwise. ## Output format, in this exact order ### 1. Summary Exactly three lines. The first line is what happened. The second line is the one number that matters most. The third line is what somebody should do about it. ### 2. Facts Only numbers that appear in, or are directly computed from, the source. A table with the figure, the value, and the comparison to the previous month as an absolute change and a percentage. Currency as EUR with German number formatting (1.234,56 EUR). Percentages to one decimal place. ### 3. Inferences Clearly labelled as interpretation, not fact. Each inference starts with "This suggests" or "A plausible reading is". At most four. Every inference names the fact it rests on. ### 4. Anomalies Anything that looks wrong, missing, stale or internally inconsistent: gaps in dates, values outside a plausible range, records referring to products or people that do not exist in the reference files, a month with no activity for a representative who had transactions. If there are none, write "No anomalies found" and say which checks you ran. ### 5. Next steps At most three. Each one is a concrete action with an owner role (not a person's name) and a deadline expressed as a week. ## Style English. Formal but not stiff. No filler openings. Do not begin with "In this report". Write dates as 19 September 2026. Name every source file you used at the very end under the heading "Sources". ## When information is missing Say exactly what is missing, in which file you expected it, and what you did instead. Never silently skip a section: write the section heading and the sentence "Not enough data in the source for this section."

Glossary

plain words
Agentic loopGather context, take action, check the result, repeat. Claude keeps cycling until the job is done or you stop it.
ArtifactA finished page from your session published to a private claude.ai link that updates in place, with version history. On Pro and Max the only way to share it is a public link.
CLAUDE.mdA plain text file of house rules in your folder. Claude reads it at the start of every session.
ConnectorA ready-made plug that lets Claude use an outside system: Gmail, Microsoft 365, Slack, Jira, Trello, Notion.
Context windowClaude's working memory for one conversation. Everything it read is in there, and all of it is re-sent on every request.
DiffThe before-and-after view of a file change. Track Changes in Word, for any text file.
Dynamic workflowA job big enough that Claude writes a script to run it: many helpers in parallel, in phases, cross-checking each other, with one file as the result.
EffortHow hard Claude thinks before answering. Five levels: low, medium, high (the default), xhigh, max.
EnvironmentWhere the session runs: Local (your laptop), Cloud (Anthropic's machines), SSH (a server you own), WSL (a Linux layer on Windows).
MarketplaceThe shelf a plugin is installed from. The official one is added for you. Community and organization marketplaces exist. An admin can restrict which ones you may use.
MCPThe standard plug socket that connectors use. You never type it in the Desktop app.
Permission modeHow much Claude is allowed to do without asking: Manual, Accept edits, Plan, Auto, Bypass permissions.
PluginA bundle installed in one go from a marketplace. It can contain skills, subagents, hooks and connectors. Treat it like a browser extension: only from sources you trust.
PromptWhat you type. A good one has scope, a pointer, what done looks like, and a check.
RoutineA saved prompt that runs on a schedule. Cloud routines run without your machine. Local ones run only while the app is open and the machine is awake.
SessionOne conversation, bound to one folder. Its own memory, its own history, its own permission mode.
SkillA folder with a SKILL.md file: a written procedure Claude pulls out when the task matches its description.
Slash commandA shortcut you type starting with a slash. Type it in the prompt box to see what your app offers.
SubagentA helper Claude sends off with its own clean context window. Only the summary comes back.
UltracodeA Claude Code setting, not an effort level. It sends xhigh to the model and additionally has Claude orchestrate a dynamic workflow. Expensive. Once a week, not every day.
Usage limitThe meter on a paid plan: a rolling five-hour window and a weekly window, shared across Claude chat, Cowork and Claude Code.
